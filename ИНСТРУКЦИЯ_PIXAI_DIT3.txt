Silly Images Plus — PixAI Tsubaki.3 / Flash API trial patch
Источник: пользовательский Silly-Images-Plus-main (18).zip

ЗАМЕНИТЬ В GITHUB ТОЛЬКО ДВА ФАЙЛА:
  src/providers.js
  src/ui.js

Другие файлы не менять (в частности manifest.json, src/settings.js, CSS и ваши пресеты).

Что изменилось:
- Tsubaki.3 Flash version ID: 2050048243034896798 (официальная страница PixAI).
- Tsubaki.3 version ID: 2024383379556065549.
- Tsubaki.2 оставлена прежней, включая режим Lite и поддержку LoRA.
- Для Tsubaki.3 / Flash параметр mode НЕ отправляется: предыдущая 422-ошибка говорила, что профиль lite неизвестен. API сам выбирает значения по умолчанию.
- Новая понятная ошибка вместо необоснованного «ваш API-ключ не поддерживается».
- Для трёх конкретных старых LoRA DiT.2 включена локальная защита от случайной отправки их с DiT.3.
- Другие LoRA остаются под контролем пользователя. Не существует универсального определения их архитектуры по одному ID.

КАК ПРОВЕРИТЬ:
1. Сохраните в «Библиотека стилей» действующий пресет Tsubaki.2 с тремя LoRA, чтобы не потерять его.
2. Замените 2 файла в репозитории, перезагрузите Силли Таверну (желательно обновить страницу без кэша).
3. Провайдер PixAI -> Обновить список моделей -> Tsubaki.3 Flash (API test).
4. Временно СНИМИТЕ ГАЛОЧКИ со всех LoRA DiT.2, в том числе старых трёх; DiT.3 требует версии DiT.3.
5. Для первого теста: размер 1k, 1 картинка, простой промпт. Запрос может потратить PixAI кредиты, если сервис примет его.
6. При HTTP 400/403/422 сохраните текст ответа PixAI БЕЗ API-ключа. Одно такое сообщение не означает автоматически ограничение подписки.
7. При успехе постепенно подключайте только совместимые DiT.3 LoRA (конкретные version IDs), сохраняя отдельный пресет для Flash.

ОГРАНИЧЕНИЕ: реальный доступ к модельному API с вашим личным ключом НЕ проверялся, автоматических повторных попыток и расходования кредитов НЕТ.
